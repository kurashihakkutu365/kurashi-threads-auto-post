## 雑談の文章

商品紹介と同様に、最初の1文だけ独立させて改行し、残りは1段落で続けます。雑談は60〜150文字。商品紹介のような価格・数字・競合比較・広告表記は必須にせず、売り込みやURLを入れません。女子のオタク系の自然な口調で、絵文字は最大2回。本人の購入・使用体験を創作しません。

「あるある・本音・共感・小さな発見・こだわり・問いかけ」の6種類を用意し、1日の3件は異なる種類にします。問いかけは連続3投稿で最大1回。過去2投稿に質問や「教えて」等の呼びかけがあると、次の問いかけを止めます。毎回質問で締めず、共感の一言や本音、余韻のある言い切りも使います。

### あるある

> 収納グッズを選んでる時間、ちょっと楽しすぎる。
> 片付けたいだけなのに、色も形もそろえたくなって急にインテリア会議が始まる。便利さだけで決められないの、おしゃれな部屋への欲がちゃんとあるから🥹。

### 本音

> 全部しまってある部屋だけが正解、とは思えない。
> 好きなマグや小さな置物まで隠すのは、なんだかもったいない。生活感を消すことより、目に入ったときにちょっと嬉しくなる景色を残したい🥹。

### 小さな発見

> 文房具の色がそろってる机って、それだけで眺めたくなる。
> 道具の数を増やさなくても、並べ方を考える時間には小さな楽しさがある。使うための場所に好きな景色も置けるの、机まわりの良いところ。

Threadsは本文のみ、Instagramは自作の1080×1080 JPEGを添付します。文章中の改行は画像でも段落境界として保ちます。画像内では読みやすさのため追加の折り返しを行います。

無料の見本は24本。過去30日の類似投稿は避け、候補不足なら枠をスキップします。24本で毎日3件を30日間維持できるとは限りません。OpenAIの雑談生成は異なる3種類を1バッチで要求し、同じ書式・質問頻度を検証します。実運用には予算設定・結果の永続割当・画像生成と定期実行の接続が引き続き必要です。

## Supabaseの更新（既存プロジェクト）

以前のRPCは7件/日、雑談2件の上限を持つため、ファイルの更新だけでは昼枠を記録できません。

1. [002_noon_daily.sql](../supabase/migrations/002_noon_daily.sql)を開き、全文をコピー。
2. 自分のSupabaseプロジェクトのSQL Editorで新しいクエリに貼り付けてRun。
3. GitHub Actionsの **Supabase connection and DRY_RUN** を`operation: check`で実行し、`scheduleVersion: 2`、`maxDailyPosts: 8`を確認。
4. 同じworkflowを`operation: run`で実行して、新しい上限でDRY_RUNが成功することを確認。

このSQLは既存のRPCを更新するだけで、既存データを削除しません。RLS・サーバー用キー限定の実行権限・排他ロック・重複防止・予算処理は保持します。再実行できます。初期構築は001→002の順に適用します。002適用前の定期実行は`supabase_schedule_update_required`で停止します。
