# OpenAIで雑談3件を1回生成するテスト

確認日: 2026-11-11（JST）。通常の有料AIと本番投稿は無効のまま、明示的に手動実行した場合だけOpenAIクレジットを消費します。自動スケジュール、Threads/Instagramへの投稿、画像入力・画像生成・楽天アクセスはありません。

## 実行する前に

* Repository Secret `OPENAI_API_KEY`が必要です。キーは画面やチャットに貼りません。今回使うAPIはResponsesのWriteです。
* 既存のSupabase Secretsと002の適用が必要です。利用予約を永続DBへ記録します。SQLiteへフォールバックしません。
* モデルが許可されていることと、クレジットが利用できることを確認します。支払方法や自動チャージの追加はこのテストの条件ではありません。

## 固定モデル・料金の見積もり

モデルは`gpt-5.4-mini-2026-03-17`。2026-11-11に[公式モデルページ](https://developers.openai.com/api/docs/models/gpt-5.4-mini)で、標準テキスト100万トークン当たり入力$0.75・出力$4.50、Responses／Structured Outputsとreasoning effort noneの対応を確認しました。Batch、Priority、検索、画像、その他ツールは使いません。

入力枠8,000・出力枠1,200トークンに対し、予約する見積もりは **$0.0114／2.28円**（見積換算レート200円/USD）。これは実勢為替や確定請求額ではありません。キャッシュ割引を見込まない計算です。プロンプトとSchemaのUTF-8バイト数にフレーム分を加えて入力枠内か確認し、返却された利用量も照合します。予想外の超過なら今後のAIを停止します。

既存の月1,000円、文章200円の目標を引き上げません。1回分をSupabase RPCで事前予約し、応答にある実トークン数から推定額を精算します。クレジット利用でも利用額として数えます。通常の`paidAiEnabled`・`production.enabled`・`hardBillingLimitVerified`は変更しません。

日本時間の同日中は、共有利用台帳のAI呼び出し数を最大1件に制限します。同日の再実行や同時実行は追加のOpenAI要求を送りません。別のAI処理が当日すでに台帳を使っていれば、このプレビューも停止します。翌日は再度手動実行できます。

タイムアウト、通信切断、401、429でも自動再試行しません。結果が不明な要求の予約は保持し、当日の再実行を停止します。出力の字数・改行・質問頻度が不合格でも、消費した生成を無かったことにはせず、再生成せず止めます。失敗時は繰り返し実行する前にログの固定エラー名を確認してください。

## GitHubでの操作

1. Actions → **OpenAI daily preview (uses credits, no posting)**。
2. Run workflow、Branchは`main`。
3. 見積もりを確認し、`spend_credits`にチェックを入れた場合だけ実行します。初期値はオフです。オフならジョブはスキップされます。
4. `Generate three daily examples once without publishing`のログで3種類の雑談を確認します。

キーボードからキーをWorkflow入力欄へ入れる必要はありません。生成文だけを表示し、HTTP認証ヘッダーやプロバイダーのエラー本文はログへ出しません。商品説明や画像の実運用準備とは別の、雑談生成1回の確認です。

`npm run openai:preview`でも同じ処理を実行できますが、実行承認とSupabaseを必要とするため通常のオフラインテストとは異なります。回帰テストは模擬HTTPのみです。

## 上限設定と残件

[現行の公式Spend limits資料](https://developers.openai.com/api/docs/guides/spend-limits)では、月額の通知と`Enforce a hard limit`による停止を区別しています。停止の反映中に少量の超過が生じ得ます。今回のユーザー画面ではSpend欄を確認できておらず、OpenAI側の上限設定を確認済みにはしていません。

そのため通常の有料AI運用は有効にせず、上記の明示的な少額テストだけを別経路で準備しました。OpenAI側の月額制限や為替を含め、絶対に月1,000円を超えないという保証ではありません。料金確認から31日を超えた場合も、再確認まで実行を止めます。
