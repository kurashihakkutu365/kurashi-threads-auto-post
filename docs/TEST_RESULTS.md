## Supabase対応の追加検証 — 2026-11-07

* 既存79件は非同期ストア対応後も成功。
* 通常の`npm test`: 93件成功、0件失敗。実PostgreSQL専用の親テスト1件は通常実行では対象外。
* `npm run test:postgres`: 12件成功、0件失敗（親テストを含む）。
* PostgreSQL 17の一時コンテナにSQLを2回適用し、冪等性と実行権限を検証。
* 独立した5接続で同一枠を同時取得しても成功は1件。媒体をまたぐ同一商品も1件だけ成功。
* 同時料金予約は予算内でのみ成功。70/85/95/100%とJST月次境界を実DBで検証。
* anon/authenticatedのテーブル読取とRPC実行を拒否。サーバー用キーのHTTPヘッダーと固定エラーコードをモック検証。
* リモートストアを通したDRY_RUN、クライアント再起動、unknown保持、キャッシュ/停止設定の永続化を検証。
* 空DBへの復元、unknown状態・画像証跡・商品番号・削除済み番号の非再利用を検証。
* AES-256-GCMの暗号化/復号、異なる鍵/改ざんの拒否、秘密情報を出さないhealth専用CLIを検証。

実PostgreSQL試験は利用者のSupabaseへ接続せず、ローカルの隔離DBだけで実行。
本番のSupabase Gateway・キーの有効性・利用者プロジェクトへのSQL適用は未確認。
楽天の公式documentation/API reference/Explorerは再確認でも503のため、実商品APIの実装は保留。

## Threads読み取り専用接続確認 — 2026-11-09（JST）

通常の`npm test`は106件成功・0件失敗・実PostgreSQL専用の親テスト1件が対象外。

* 認証ヘッダー付きGETだけを1回実行し、期待ユーザーネームと任意の既存ユーザーIDを照合。

* 無効/期限切れ、権限不足、レート制限、通信切断、不正JSON、別アカウントを拒否。
